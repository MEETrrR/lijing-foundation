# 砺境器灵学习陪伴 Agent 技术实现方案

**版本：** v1.0
**日期：** 2026-09-09
**状态：** P1 每日循环已实现；结构化 Agent、重排和周回望待实施
**适用范围：** 大学生 28 天封闭试点

## 1. 目标与边界

砺境的首期核心不是扩充考试知识库，而是验证“器灵能否让用户持续完成学习行动”。器灵是一个受服务端状态、权限、成本和安全策略约束的学习陪伴 Agent，不是开放式聊天机器人。

首期必须完成的闭环：

```text
用户建档
  -> 生成本周可执行路线
  -> 器灵给出今日唯一行动
  -> 用户提交完成证据或阻塞原因
  -> 器灵鼓励、缩小任务或重排计划
  -> 用户确认可长期记住的策略/困难
  -> 每周回望并生成下一周行动建议
```

首期不做：

- 不承诺覆盖全部考研、公考或职业技能内容。
- 不让模型自行宣布用户已掌握知识、获得奖励或完成目标。
- 不做未获授权的外部消息推送、自动代办或高频骚扰提醒。
- 不将原始长对话、Provider 密钥或完整敏感资料写入日志。

## 2. 已有基础与改造原则

当前代码已经提供以下可复用能力：

| 已有能力 | 现有职责 | 器灵方案中的用途 |
|---|---|---|
| `UserStateService` | 用户资料、目标、当日任务、学习证据和知识节点 | 读取用户可用时间、目标和当前页面状态 |
| `LearningRouteService` | 路线草案、确认和刷新 | 提供本周计划与受约束的重排入口 |
| `MemoryService` | 用户确认的困难和策略记忆 | 形成经用户确认的长期陪伴上下文 |
| `CompanionService` | 器灵选择、互动次数和最近主题 | 保留器灵身份与轻量互动档案 |
| `AiGatewayService` | 配额、幂等、审计、Provider 调用和降级 | 统一执行模型请求，不允许客户端直连模型 |
| `KnowledgeRetrievalService` | 审核来源与检索证据 | 仅为高风险、时效性事实提供来源核验 |

改造原则：器灵循环只编排已有领域能力，不直接修改其他领域的持久化记录。它拥有自己的“每日循环、干预和周回望”事实；用户资料、路线、长期记忆和 AI 使用记录仍由各自模块拥有。

## 3. 模块边界

新增领域：`services/api/src/domains/companion-cycle/`。

| 模块 | 拥有的事实 | 器灵循环可读取/调用 | 禁止行为 |
|---|---|---|---|
| Companion Cycle | 当日循环、签到、阻塞分类、干预建议、周回望版本 | Profile 状态、路线投影、已确认记忆、AI Gateway | 直接改写用户资料、路线或长期记忆 |
| User Profile | 用户资料、偏好、提醒授权、目标选择 | 向器灵循环提供受限资料投影 | 接受模型直接写入的偏好或事实 |
| Learning Route | 路线、任务、版本与确认状态 | 提供今日任务，接受明确的刷新请求 | 由客户端或模型伪造完成状态 |
| Memory | 用户确认的策略、困难和学习偏好 | 返回已确认记忆，接收候选确认 | 自动把模型判断升级为长期记忆 |
| Companion | 器灵身份、主题与互动计数 | 提供器灵人格版本 | 保存学习结论或敏感原文 |
| AI Gateway | 模型请求、配额、审计和 Provider 适配 | 处理结构化行动建议请求 | 直连客户端、无配额调用 |
| Knowledge Retrieval | 官方来源与审核片段 | 只在需要事实依据时检索 | 作为日常陪伴的唯一上下文 |

## 4. 数据模型

首期可继续使用现有服务端 KV 适配器；生产放量后再迁移为结构化表。所有键都以认证后的 `actorId` 作用域隔离。

### 4.1 当日器灵循环

建议键：`companion:cycle:<actorId>:<YYYY-MM-DD>`。

```json
{
  "version": 1,
  "date": "2026-09-09",
  "status": "planned|started|completed|stuck|replanned|skipped",
  "route_id": "route-...",
  "task": {
    "id": "task-...",
    "title": "完成极限专题的 5 道错题复盘",
    "estimated_minutes": 25
  },
  "check_in": {
    "energy": "low|normal|high",
    "intent": "start|complete|stuck|skip",
    "blocker_type": "time|difficulty|emotion|environment|unknown|null",
    "evidence_level": 1,
    "evidence_hash": "sha256..."
  },
  "intervention": {
    "type": "encourage|reduce_scope|reschedule|recover|review",
    "next_action": "先完成其中 2 道错题，并在 20 分钟后提交结果。",
    "source": "template|ai",
    "policy_version": "..."
  },
  "created_at": "...",
  "updated_at": "..."
}
```

原始学习证据只在用户明确提交的学习记录中按最小必要范围保存；器灵循环默认保存哈希、分类和结果，不把完整自由文本复制进审计日志。

### 4.2 周回望

建议键：`companion:weekly-review:<actorId>:<ISO-week>`。

字段包括：计划任务数、完成任务数、证据次数、常见阻塞类型、有效干预类型、用户确认的策略候选、下周可执行建议和生成版本。

### 4.3 长期记忆

继续由 `MemoryService` 保存。只有用户确认或编辑后的候选，才会进入 `active` 状态并作为后续器灵上下文。模型生成的候选不可直接视为事实。

## 5. Agent 决策流程

### 5.1 上下文组装

器灵请求只组装最小必要上下文：

```text
认证用户
  + 当前目标与可投入时间
  + 已确认路线中的今日任务
  + 最近 7 天完成/阻塞摘要
  + 用户确认的 active 记忆
  + 当前签到意图
  + 必要时的官方事实证据
```

不得将完整历史对话、全部知识节点、完整个人笔记或未经确认的记忆候选无差别注入模型。

### 5.2 决策状态机

```text
planned
  -> start      -> started
  -> complete   -> completed
  -> stuck      -> stuck -> reduce_scope | reschedule | recover
  -> skip       -> skipped -> recover
  -> seven_days -> weekly_review
```

服务端先根据确定性规则判定状态，再决定是否需要模型参与：

- 已完成：返回确认、证据记录和下一次回望提示，默认不调用模型。
- 首次卡住：优先使用模板化追问，收集阻塞类型。
- 连续两次卡住或任务超时：调用模型生成结构化干预候选。
- 连续三天未开始：生成恢复建议，任务必须缩小且允许用户拒绝。
- 周末或达到七天周期：生成结构化周回望和记忆候选。

### 5.3 模型输出约束

模型仅能返回经 JSON Schema 校验的对象：

```json
{
  "intervention_type": "encourage|reduce_scope|reschedule|recover|review",
  "reason": "不超过 160 个字符",
  "next_action": "不超过 160 个字符",
  "estimated_minutes": 5,
  "memory_candidates": [
    { "kind": "friction|strategy", "content": "不超过 200 个字符" }
  ],
  "requires_user_confirmation": true
}
```

服务端验证任务时长、候选数量、文本长度、枚举值、敏感输出和当前路线边界。校验失败、超时或 Provider 不可用时，统一返回模板化干预，不伪装为模型成功。

## 6. RAG 使用策略

RAG 不再驱动日常陪伴。仅在以下条件同时成立时调用：

1. 用户问题涉及考试政策、报名资格、院校条件、职位要求或证书规则；
2. 信息具有时效性或错误成本高；
3. 审核来源中存在可展示的依据。

若没有证据，器灵必须返回“需要核验”的行动项，而不是编造结论。日常任务拆解、情绪支持、任务缩小和复盘优先使用用户状态、已确认记忆和确定性规则。

## 7. HTTP 契约

新增接口全部要求认证、`request_id` 和写请求的 `Idempotency-Key`。本次已实现 `GET /api/v1/companion/today` 和 `POST /api/v1/companion/check-ins`；重排、周回望和时间线接口仍属于后续阶段。

| 接口 | 用途 | 关键输出 |
|---|---|---|
| `GET /api/v1/companion/today` | 读取今日任务、循环状态和下一步 | `cycle`、`next_action`、`reminder_eligible` |
| `POST /api/v1/companion/check-ins` | 提交开始、完成、卡住或跳过意图 | `cycle`、模板化追问或干预建议 |
| `POST /api/v1/companion/replans` | 用户确认后请求缩小/延期/恢复计划 | 新任务建议、是否需要路线刷新 |
| `POST /api/v1/companion/weekly-reviews` | 生成或读取当周回望 | 周摘要、记忆候选、下周行动 |
| `GET /api/v1/companion/timeline` | 读取脱敏成长时间线 | 周期、完成摘要、确认记忆 |

所有写操作从会话取得 `actorId`，不接受客户端提交的用户 ID、掌握度、奖励、连续天数或最终完成结论。

## 8. 前端实现

### 8.1 首期页面调整

- 首页：展示“器灵今日同行”，将今日唯一行动置于首屏。
- 攀登页：提交学习证据后立即呈现器灵干预或确认反馈。
- 回望页：展示每周行动、阻塞、有效策略和待确认记忆。
- 引路页：保留器灵人格和对话，但对话入口必须能跳回“今日行动”。
- 档案页：展示用户授权、提醒偏好和器灵可使用的长期记忆。

### 8.2 交互约束

- 首次建档控制在五个字段内：目标、截止时间、每周可投入时间、当前状态、首要困难。
- 日常操作优先使用“开始”“完成”“卡住”三个明确动作。
- 用户可拒绝、编辑或删除记忆候选。
- 未实现外部推送前，提醒只显示为应用内“到点且有未完成任务”的状态，不能宣称已通知用户。

## 9. 埋点、成本与安全

### 9.1 核心事件

```text
companion_onboarding_completed
companion_today_viewed
companion_check_in_submitted
companion_evidence_submitted
companion_intervention_shown
companion_replan_accepted
companion_replan_rejected
companion_memory_confirmed
companion_weekly_review_completed
```

事件只记录匿名用户维度、目标类型、循环状态、干预类型、耗时分桶和 AI 结果状态。禁止写入邮箱、证据原文、完整对话或自由文本标签。

### 9.2 成本控制

- 完成确认、首次卡住追问和普通提醒优先使用模板，不调用模型。
- 每用户每日 Agent 调用额度独立于通用 AI 对话额度。
- 对同一循环、同一输入和同一幂等键复用结果，避免重复扣费。
- 记录每次模型请求的输入/输出 token 估算、Provider 状态、降级原因和 feature。
- 超出预算、触发风险策略或 Provider 异常时降级为模板，不影响用户提交证据。

### 9.3 数据与合规

- 记忆候选必须可见、可确认、可编辑、可拒绝。
- 对未成年人或敏感情绪输入采用更严格的提示、人工支持入口和内容策略。
- 用户注销或删除请求必须覆盖器灵循环、记忆、路线和相关审计保留策略。
- 面向公网前，完成隐私政策、数据分类、内容安全、Provider 数据边界和生成式 AI 服务合规评审。

## 10. 分阶段实施

| 阶段 | 交付 | 验收 |
|---|---|---|
| P0：契约与状态 | 新领域边界、OpenAPI、JSON Schema、迁移/键规范 | 契约测试覆盖认证、幂等和非法状态 |
| P1：每日循环 | `today`、签到、证据、模板化干预 | 不同用户隔离；重放不重复写入；无 AI 配置可用 |
| P2：受控 Agent | 结构化模型输出、重排和降级 | AI 失败不伪装成功；输出不能越权改写路线 |
| P3：回望与记忆 | 周回望、候选记忆、确认/拒绝/编辑 | 未确认记忆不注入长期上下文 |
| P4：试点与分析 | 埋点、成本看板、邀请码、反馈和试点报告 | 真实账号跨重启持久化、隐私与成本检查通过 |

## 11. 测试要求

新增测试至少覆盖：

- 未认证请求、跨账户读取和跨账户写入被拒绝。
- 每个写接口的幂等重放与冲突复用行为。
- 用户无法提交最终完成状态、奖励、掌握度或其他服务端事实。
- 连续卡住、恢复、重排和周回望的状态机迁移。
- 模型输出字段越界、枚举错误、敏感内容、空输出和超时时的模板降级。
- RAG 无可用来源时，输出待核验事项而不是事实结论。
- 记忆候选在用户确认前不可进入 `active` 上下文。
- telemetry 不包含邮箱、原始证据、完整对话或 Provider 密钥。

## 12. 28 天试点验收指标

本方案进入下一阶段前，应使用真实账号与持久化数据库验证：

| 指标 | 目标线 |
|---|---:|
| 建档后完成首个任务比例 | >= 60% |
| D7 留存 | >= 35% |
| D28 留存 | >= 20% |
| 活跃用户每周学习证据 | >= 3 次 |
| 失速后 48 小时内回归比例 | >= 40% |
| 用户对“器灵理解当前状态”的评分 | >= 4/5 |
| 有明确付费意愿的用户比例 | >= 5% |

这些指标是试点门槛，不是当前经营数据。若 D28 留存低于 15%，或失速用户回归低于 25%，应暂停扩展新目标类型，先复盘器灵干预策略、首日价值和任务粒度。

## 13. 完成定义

该方案只有在以下事实都成立时，才能称为“器灵学习陪伴 Agent 已完成首期实现”：

1. 真实注册用户可跨重启读取自己的器灵循环、路线和确认记忆。
2. 今日行动、学习证据、卡住、重排和周回望形成可验证闭环。
3. Agent 的模型调用经过 AI Gateway，具备配额、审计、幂等、输出校验和模板降级。
4. RAG 只在必要的高风险事实场景提供可追溯来源。
5. 28 天试点数据能回答留存、回归、成本、付费意愿和用户价值问题。
