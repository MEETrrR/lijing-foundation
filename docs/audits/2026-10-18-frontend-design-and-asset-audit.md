# 砺境前端审查：从字体到框架

**日期：** 2026-10-18（第二轮更新）
**范围：** `apps/user_client`（原生 Web Modules，无构建步骤，源码直出）与 `assets/generated`
**方法：** 全部结论来自脚本实测。工具在 `_ljing_audit/`：CSS 解析器、对比度计算、
CDP 沿 DOM 合成背景后的真实对比度探针、焦点可见性探针、几何回归探针、
全宽度响应式扫描、多视口截图、资源体积普查、字体 cmap 校验。
**限制：** 应用主体在登录墙后，本地用桩住 `/api/v1` 的 harness 渲染。未做读屏器实机测试；
未测真实网络下的 LCP/CLS；`/admin`、`/map`、`/cet`、`/route` 的表单态未逐一目检。

---

## 1. 结论摘要

按影响从大到小，只有四条真正重要：

1. **资源层是全站最大的问题，而且已经解决了一半。** 仓库带 54 个图片/视频共
   **114.8 MB**，其中 **41 个从未被任何代码引用（84.1 MB）**；被引用的 10 张图全是 PNG，
   合计 27.1 MB。但仓库里**已经存在**这些图优化好的、带内容哈希的 WebP 版本，
   只是 11 个里只有 1 个接进了 `assets.js`。补上接线后首页首次传输从
   **3,585 KB 降到 759.6 KB（-79%）**，底图单张从 2,887 KB 降到 61 KB。

2. **品牌字形此前完全由访客的操作系统决定。** `document.fonts.size = 0`，全站零 `@font-face`：
   Windows 走楷体、macOS 走 STKaiti、Android 与 Linux 没有中文衬线，整站「水墨/东方」气质
   直接塌成无衬线。已自托管按站点实际字符集子集化的霞鹜文楷（993 码位，197 KB woff2）。

3. **纸面容器里的文字全部不达标。** 用 CDP 沿 DOM 合成真实背景后实测，8 条路由上有
   16 个选择器低于 4.5:1，最严重的只有 **1.08:1**（暖白文字压在纸面上，几乎看不见）。
   根因是深底梯度被用在了纸面上——而极深与极浅两种底上，不存在同一支颜色能同时达标。
   已按底拆成两套梯度，修后 8 条路由 **0 个不达标**。

4. **排印和间距此前没有刻度。** 51 个字号档位（正文只有 8–11px）、71 个间距取值、
   18 种文字 alpha、15 种描边 alpha、同一个纸面卡片底写了 8 个值。已收敛为
   10 个字号令牌、12 档间距、3 档文字、3 档描边、2 档纸面。

## 2. 逐层发现

### 2.1 资源层（已部分修复）

| 项目 | 实测 |
|---|---|
| 资源总数 | 54 个（png 41 / webp 11 / mp4 1 / svg 若干） |
| 总体积 | 114.8 MB |
| 被引用 | 13 个，30.6 MB |
| **从未被引用** | **41 个，84.1 MB** |
| 首页首次传输（修前 → 修后） | 3,585 KB → **759.6 KB** |

- 单张最大的 `aaa-home-title-screen-v1.png` = **14.79 MB**，另有 `aaa-hero-character-v1.png`
  6.29 MB、`aaa-ui-home-reference-v1.png` 5.16 MB，三张都是设计稿，无任何代码引用。
- `professions/` 与 `professions-cn/` 下的职业立绘约 **55 MB**，同样无引用——疑似未完成的功能资产。
- 被引用的图片原先全部是 PNG 且**文件名不含内容哈希**，因此拿不到长期缓存。
- 仓库已有的 WebP 版本体积小 **31–76 倍**，逐像素比对 MAE 仅 **0.93–1.44**（肉眼不可辨）。

**已修：** 9 条 `path` 切到已有的哈希 WebP，用户可见图片体积 27.1 MB → **549 KB**，
并顺带拿回 `immutable` 长缓存。

**另外修掉一张高成本的图：** `og:image` 原指向 `lijing-horizon-ink-v1.png`，
**2,955,718 B 且是 1024×1536 竖图**，而 Open Graph 的标准比例是 1.91:1。
多数抓取器对分享图有体积上限，2.8 MB 会被拒或超时，竖向构图在信息流里还会被裁坏。
已换成 1200×630 的 JPEG（94,204 B），并补上 `og:image:width/height`。
选图时弃用了另一个尺寸更合适的候选 `aaa-home-title-screen-v1.png`——
它是**蓝调 + 西式城堡**，正是已被否掉的蓝色方向，这也印证了那批 `aaa-*` 是废弃稿。

**未修（需决定）：** 84.1 MB 未引用资源未删除。它们是仓库体积与克隆时间的主因，
但 `professions*` 可能对应正在做的功能。建议：确认无用的移出仓库或转 Git LFS；
三张 `aaa-*` 设计稿建议移到 `docs/` 或外部设计库。

### 2.2 字体层（已修复）

| 项目 | 修前 | 修后 |
|---|---|---|
| `@font-face` 数量 | 0 | 1 |
| `document.fonts.size` | 0 | 1（status = loaded） |
| 字体族写法 | 8 种 / 120 处内联 | 4 个令牌 / 0 处内联 |

- 源字体 23.6 MB → 子集 **201,984 B（197 KB）**，压缩比 0.8%。
- 字符集来自客户端源码扫描：**898 个不同汉字 + 95 ASCII = 993 码位**；
  用 fontTools 校验字体 cmap 与字符集**完全一致**（993 = 993，缺失 0、多余 0）。
- `unicode-range` 精确声明这 993 个码位，而不是图省事写 `U+4E00-9FFF`：
  **字体声明拥有的码位若缺字形，浏览器不会回落系统字体，而是渲染空白/豆腐块**，
  用户动态输入的汉字会直接消失。这是本次最容易踩的坑。
- CJK 全宽等宽，9 个汉字在子集与 `sans-serif` 下宽度都是 160.0px，**换字体零布局位移**。
- 许可证 SIL OFL 1.1，`NOTICE.md` 与 `OFL.txt` 随字体分发。

**第二轮补充：楷体退出正文。** 视觉方向调研给出的判定是「楷体绝不能做正文」——
楷体横画极细、起收笔有提按，12–18px 抗锯齿后笔画断续，连续阅读时字形节奏会抢走注意力；
W3C《中文排版需求》的正文惯例（五号 / 行高 1.5 倍 / 行长 20–40 汉字）本就是为字面方正的
宋体与黑体定的。落地时发现 `--font-reading` 这个令牌把**两类语义混在了一起**：
它既服务正文段落，也服务印章、卦象符号、头像字、引文——后者恰恰是该用楷体的地方。
而且它的名字本身已经误导（它实际是楷体角色）。所以不是换一个字体，而是按角色拆分：

| 令牌 | 用途 | 引用数 |
|---|---|---|
| `--font-kai` | 标题、引文、印章、卦象、头像（原 `--font-reading` 改名并并入 `--font-serif-kai`） | 56 |
| `--font-prose` | 正文段落、列表、说明（新增，指向宋体子集） | 34 |
| `--font-display` | 品牌展示大字 | 46 |
| `--font-interface` / `--font-mono` | 界面表单 / 代码数字 | 3 / 46 |

宋体子集同样从 993 字符集切出（11.1 MB → **227 KB**），fontTools 校验两者 cmap
**完全一致（993 = 993，零差异）**。中途修掉一个会让排版露馅的问题：第一次只用了
898 个汉字的字符集，子集缺 95 个 ASCII 码位，正文里的拉丁字母和数字会回退到另一种字体、
出现行内混排。两份子集共 424 KB，都在首屏出现，因此都做了预加载。

### 2.3 排印层（已修复）

| 项目 | 修前 | 修后 |
|---|---|---|
| 字号档位 | 51 | 10（内容 7 + 展示 3） |
| 8–11px 的字号声明 | 330 处 | 0 |
| 裸 px 字号 | 518 处 | 0 |
| 同一个 `.section-title h2` | 30/31/36/38px 四种 | 单档 |

- 内容阶梯 7 档 12/14/16/18/22/28/36；展示阶梯 3 档 56/72/`clamp(88px,8vw,116px)`。
- 展示阶梯单独成组，因为它们是**桌面与移动成对出现**的响应式意图
  （如 `.home-hero h1` 桌面 116 / 移动 78），硬压成一档会破坏响应式设计。
- 表单控件统一 16px，修掉 iOS 聚焦自动放大页面的问题。

### 2.4 色彩层（已修复）

| 项目 | 修前 | 修后 |
|---|---|---|
| 文字 alpha 种数 | 18（.55–.86） | 3 档（`--ink-1/2/3`） |
| 描边 alpha 种数 | 15（.07–.24） | 3 档（`--rule-ink-soft/base/strong`） |
| 纸面卡片底取值 | 8 个（.86–.98） | 2 档（`--surface-paper/-muted`） |
| 水洗底 alpha 种数 | 11（.045–.2） | 2 档 |
| 纸面上不达标元素 | 16 个选择器 | **0** |

- 深底文字层级实测：`.92`=12.89:1、`.72`=8.25:1、`.58`=5.73:1、`.55`=5.29:1，`.55` 为绝对下限。
- 纸面文字层级（`#eeeae0` 上）：`#1b2528`=13.03、`#33403f`=8.98、`#4a5654`=6.36、`#5c6a6b`=4.69。

**修掉的纸面不达标（实测 8 条路由）**

| 颜色 | 纸面上对比度 | 处理 |
|---|---|---|
| `--rock` #74807e | 3.15:1（全站 110 处） | 纸面作用域内换 `--paper-3` → 6.36:1 |
| `--gold-light` #e4bd70 | 1.37:1 | 作为文字用时换 `--gold-on-paper` → 5.22:1 |
| `--teal` #76a19d | 2.20:1 | 换 `#2f625e` → 5.77:1 |
| `--red` #a94b40 | 4.29:1 | 纸面上换 `#9c4034` → 5.47:1 |
| 暖白 `--paper` 当文字用 | **1.08:1** | 纸面作用域内的描边按钮改 `--paper-1` → 13.03:1 |

做法是利用自定义属性沿 DOM 级联的特性，只在纸面容器上重新绑定一次。
两个必须避开的坑（都实测踩过）：`--gold-light` 同时被当背景色用（28 处），
remap 会连按钮底色一起改掉；纸面容器里嵌着深色子面板（`.study-aside__tip` 等），
级联会漏进去，需要在那些子面板上把深底梯度声明回来。

**未做：** 把 `--paper` 从「卡片」提升为「页面底」。这是收益最大的视觉改动，
但会改变全站观感，需你确认方向。

### 2.5 间距层（已修复）

| 项目 | 修前 | 修后 |
|---|---|---|
| 间距取值 | 71 | 12 |

### 2.6 布局与对齐（已修复）

**修前同一屏上有三个互不相关的垂直轴**（`/privacy` 实测）：

| 元素 | 修前 | 修后 |
|---|---|---|
| 顶栏品牌 | 110px | 56px |
| 页面标题 h1 | 56px | 56px |
| 法务文档框 | 231px | 56px |
| 文档内文字 | 289px | 114px |
| **跨度** | **289px** | **114px** |

根因是 `.topbar` 写死的 `padding-left: 110px` 是早期左侧边栏的遗留
（`.app-frame` 的 `margin-left` 早已归零，110px 没人再对齐它）。
现在顶栏与 `.page-view` 共用同一算式 `max(0px, (100% - 1440px) / 2) + var(--gutter)`，
因此**超过 1440px 的宽屏也不会错开**：1920px 下顶栏、标题、文档框全部落在 289px。
剩下的 114px 是面板自身内边距，属设计如此。

### 2.7 CSS 架构层

| 项目 | 实测 |
|---|---|
| `styles.css` | 约 196 KB / 1,700 余条规则 |
| 断点 | 7 个：700(×11) / 701 / 860 / 900 / 980 / 1040 / 1180 |
| `!important` | 35 处 / 16 条规则（其中 9 条在 `@media print`，合规） |
| 设计令牌 | tokens.css 定义 50 个，**33 个被引用（66%）** |

**关于断点的更正：** 我第一版报告把「700 与 701 并存」列为「补丁而非设计」，**这是错的**。
`@media (max-width: 700px)` 与 `@media (min-width: 701px)` 是一对**互补条件**，
合起来无缝隙覆盖全部宽度，是正确写法。
并且实测 4 条路由 × 18 个宽度（320 → 1920）= **72 次检测，0 处横向溢出**。
所以断点虽然多，但功能是正常的；把它们合并只是代码洁癖，
零用户收益且有回归风险，**建议不做**。

**令牌采用率 66%**：`design-lint.mjs` 会把未采用令牌列出来，避免悄悄闲置。

### 2.9 可访问性（已修复）

**对比度：** 见 2.4，8 条路由由 16 个不达标降到 0。

**键盘焦点**（新增探针逐个聚焦并读取 outline / box-shadow / border-color 三种指示）：

| 项目 | 修前 | 修后 |
|---|---|---|
| 基础焦点规则覆盖的元素 | button / a / input | a / button / input / select / textarea / summary / [tabindex] |
| 无替代指示地抹掉 outline | 9 处 | 0 |
| 聚焦后无可见指示的元素 | 10 个 | **0**（6 条路由 103 个元素全检） |

根因：`select` 与 `textarea` 从未被基础规则覆盖；9 处类选择器用 `outline: 0`
把指示直接抹掉；`.primary-nav__link` 的 `:focus-visible` 与 `.is-active`
样式几乎相同，导致当前页那一项聚焦时看不出变化。

**跳转链接：** `main` 早已有 `id="main-content"` 与 `tabindex="-1"`，只缺链接本身。
已补上 `.skip-link`，实测是文档中第一个可聚焦元素、未聚焦移出视口（top=-50px）、
聚焦滑入（top=8px）且有焦点环。常驻隐藏用 `translateY` 而不是 `display:none`，
后者会被部分读屏器忽略。

**减少动态效果：** 复查确认第 1202 行早已有完整的 `*, *::before, *::after` 重置，
本来就处理好了。（我一度以为只有 2 条规则响应，写了个多余的块，已删除。）

### 2.10 视觉方向调研（未实施，需你定方向）

除自查外，另做了一轮联网视觉方向调研（可用来源见下）。三条判定与我的实测互相印证，
其中前两条我判断证据充分，第三条属于产品决策，留给你决定。

**判定一：深底全屏插画当页面底，对「每天来记录」的工具是净损失。**
正极性（深字浅底）在阅读速度与准确度上稳定优于负极性，机制是浅底使瞳孔收缩 → 景深增大、
像差减小、小字边缘更锐；深底使瞳孔放大 → 亮字泛光，小字号最吃亏
（Bauer & Cavonius 1980 / Buchner & Baumgartner 2007 / Piepenbrock 2013）。
NN/g 的定位是：深色模式属**情境化替代主题**，不宜做大量持续文本阅读的默认。
调研还指出 Linear 的先例不适用——它深色优先成立是因为 90% 界面是状态信号而非段落阅读。
对砺境的四项具体损失：中文笔画密、白字细横线在深底上直接消失；深底会诱导金色越调越亮、
最后失去纸面金箔感；纸面卡片 `#eeeae0` on `#0d171a` = **15.14:1**，每张卡片都是屏幕里的灯；
插画要压住文字就得降对比，等于牺牲墨分五色。
**建议方向：** 工作台/笔记/计划/证据/设置改用纸面当页面底（`#eeeae0`，卡片 `#f7f4ee`，
文字 `#1f2b2f`），墨底只留给未登录首页、登录页、里程碑、年度回望。
这与「保留水墨/纸面关系」的约束不冲突——是把水墨从**背景**升格为**章节**。
**我没有实施**：它会改变全站观感且涉及上千条规则，调研本身也建议先只翻
「笔记列表 + 输入框」两处做 A/B。半途而废比现状更差，所以留给你定方向。

**判定二：楷体不能做正文。** 已实施，见 2.2。

**判定三：已登录首页第一屏应是输入框 + 今日任务，不是 116px 标题压满屏远山。**
NN/g 认为首屏承担「建立方向感 + 主行动入口」，GOV.UK 服务设计第一条即「从用户需求出发」。
参数上 116px 已是 display 级，到正文 16px 是约 7× 跳变、中间没有台阶，
这正是只能靠金/朱砂区分层级的根源。同类产品里 flomo 打开即输入框、Things 3 打开即今日列表。
**我没动**：这是首页信息架构的重排，属于产品决策，且与上面第一条应一起做。

**另外两条已核对、结论是「不必改」：**
- 宣纸色：`#eeeae0` 落在「熟宣/米白」区间内（生宣米白 `#F3EFE3`、熟宣暖白 `#EEE7D7`），合理。
  宣纸本身无官方固定色值，随原料批次与光源变化（UNESCO 非遗条目）。
- 强调色数量：调研建议强调色收到 2 个（金 = 纸面专用，朱砂 = 语义专用），
  这与我在 2.4 已做的按底拆梯度方向一致；墨底金色它建议改用 `#c9a961`（8.08:1），
  比现值 `#e4bd70`（10.23:1）更「墨」。这是审美取舍且会**降低**对比度，
  我保留了现值，如果你要更沉的墨色可以换成前者。

## 5. 过程中的四个自我纠正

记录下来，因为「改完」不等于「改对」：

1. **`--paper` 重名**：`styles.css` 里本就有 `--paper: #eeeae0`（实心纸色，用于深底浅字）。
   `tokens.css` 先加载会被它覆盖，我一开始用它命名半透明纸面，迁移后纸面会变成
   完全不透明、丢掉 3% 透光。已改名 `--surface-paper`，并给 lint 加了重名检查
   （已验证故意造冲突会报错）。
2. **焦点作用域过宽**：起先把 `.settings-service` 误列为纸面容器（它其实是深底），
   且 remap `--gold-light` 把 `.button--primary` 的底色一起改成了 2.9:1。
   已收紧作用域并在深色子面板上声明回深底梯度。
3. **断点判断错误**：把 `700/701` 当成补丁。实际是互补条件，且 18 个宽度实测无溢出。
   已在 2.7 更正，并明确建议不做合并。
4. **子集漏了 ASCII**：给宋体做子集时第一次只用了 898 个汉字的字符集，
   缺 95 个 ASCII 码位。这会让正文里的拉丁字母和数字回退到另一种字体、出现行内混排——
   是肉眼可见的排版事故。改用完整的 993 字符集后校验 cmap 完全一致。
   另外我一度以为「8 组 @keyframes 只有 2 条 reduced-motion 规则」并写了个全局压时长的块，
   复查发现第 1202 行早有完整的全局重置，已把那个多余的块删掉。
