# 砺境「云海登山」全局 UI 设计规范

**日期：** 2026-09-03
**状态：** 第一阶段演示已实现；真实 API 与生产业务仍待接入
**范围：** Web 用户端视觉基座、页面叙事、导航、转场、状态反馈与响应式规则

## 1. 设计目标

砺境是一套 AI 学习 RPG。产品的主叙事不是“看见一张漂亮的山水图”，而是让用户把每一次真实的自律感知为登山动作：从山脚遥望、穿越云海、抵达山脊，最终登顶并回望来路，再进入下一段人生副本。

本轮设计建立一套可复用的体验基座，使首页、学习流程、计划、复习、AI 助手、成长、地图、个人中心、权限与错误状态都属于同一个世界，同时保证学习内容、题目、数据和按钮始终优先可读、可操作。

当前仓库已经包含可运行的 `apps/user_client` Web 用户端壳层和演示数据适配面；真实 API 接入仍沿用 `/api/v1` 契约，不在客户端伪造服务端掌握度、奖励或结算结果。当前演示聚焦考研数学二的 14 天学习证据试点，具体验证结果见 `docs/superpowers/evidence/2026-09-04-cloud-mountain-ui-verification.md`。

### 当前实现状态

- 已实现：统一 App Shell、八卦功能目录与全屏导航、模块化水墨背景、个人知识证据脉络、证据提交与演示复盘、无性别引路灵器选择、龙凤升腾转场、响应式和减少动效支持。
- 尚未实现：真实身份、服务端持久化、AI Gateway 调用、正式掌握度/奖励结算、素材正式审核和生产部署。
- 约束：当前所有页面数据仍是 `DEMO_STATE`，演示交互不能被理解为生产业务事实。

## 2. 核心体验叙事

### 2.1 世界隐喻

| 产品概念 | 世界表达 | 用户感受 |
| --- | --- | --- |
| 学习进度 | 山路高度、营地与山脊 | 我正在向上走 |
| 每日任务 | 山门、石阶、行旅节点 | 今天只需要走下一步 |
| 知识图谱 | 群峰、八方卦位与星轨 | 知识彼此连接 |
| 掌握度 | 卦爻完整度与墨色深度 | 我真正站稳了 |
| 复习 | 回环路线与下撤补给 | 我在加固来路 |
| AI 助手 | 云中灯火与引路人 | 我知道下一步去哪里 |
| 成长等级 | 登峰碑、印记与气韵 | 我的世界因坚持改变 |
| 阶段完成 | 破晓登顶与回望全景 | 我已经走过曾经遥远的路 |
| 新章节 | 远方新山系 | 人生副本开启下一阶段 |

### 2.2 四段页面结构

每个主要页面沿用同一套叙事骨架：

1. **入口场景：** 显示当前章节、方位和远景目标。
2. **核心内容：** 以纸面内容层承载真实功能，避免正文被背景和动效压住。
3. **状态反馈：** 使用山路、太极、卦爻、云隙和星轨表达变化。
4. **下一步行动：** 只保留一个主要行动，次要行动按优先级退后。
5. **离开与转场：** 通过云层、长卷或山路继续进入下一章。

## 3. 页面章节与路由

第一阶段的 Web 用户端以单一世界壳层承载以下路由。路由名称保持稳定，后续接入真实 API 时只替换数据适配层，不重写页面结构。

| 路由 | 章节名 | 第一屏入口 | 核心操作 |
| --- | --- | --- | --- |
| `/` | 山脚 · 遥望 | 云海山门与远方峰顶 | 开始今日学习、查看当前高度 |
| `/auth` | 入山 | 低雾中的山门与身份印记 | 登录、注册、恢复会话 |
| `/goals` | 定向 | 八方山口与目标选择 | 选择方向、时间与目标 |
| `/plan` | 行旅 | 山脊路线、营地与今日节点 | 查看计划、调整今日行动 |
| `/study` | 攀登 | 当前山段与学习任务 | 开始任务、提交学习意图 |
| `/review` | 回望 | 回环路径与复习营地 | 完成复习、查看待巩固知识 |
| `/knowledge` | 群峰 | 八卦方位、知识峰群与星轨 | 浏览知识点、查看掌握状态 |
| `/assistant` | 引路 | 云中灯火与引路者 | 提问、解释、获得下一步建议 |
| `/growth` | 登峰碑 | 角色、印记、等级与成就 | 查看成长、解锁记录 |
| `/map` | 山海图 | 章节山系与已达路线 | 进入关卡、查看路线状态 |
| `/profile` | 行者档案 | 个人印记与登山记录 | 资料、偏好、通知、设置 |
| `/state/*` | 风雨之间 | 统一状态场景 | 加载、错误、空数据、审核、权限 |

真实业务未接入时，页面上的数值、路线和成就必须带有演示态标识，不得伪装成真实用户结果、机构数据或已完成的服务端结算。

## 4. App Shell 与导航

### 4.1 桌面端

- 左侧为窄幅“山脊导航”，使用八方方位与卦爻状态，不使用传统后台侧栏文字堆叠。
- 中央为页面内容场景，顶部只保留当前章节、网络状态、通知和个人入口。
- 右侧在需要时展开“引路层”，用于 AI 助手、任务详情和上下文信息。
- 导航展开时表现为八卦盘从山门中心打开，收起时保持当前方位和一条细金线提示。

### 4.2 移动端

- 底部保留四个最高频入口，完整八方导航通过一个中心太极按钮展开。
- 触摸目标最小 44px，页面不依赖 hover 才能理解或操作。
- 复杂远景视差降级为单层云海和轻微位移，核心任务区域保持静止。

### 4.3 导航语义

- 首页：中宫 / 山门
- 目标：乾位 / 定向
- 计划：艮位 / 行旅
- 学习：离位 / 攀登
- 复习：坎位 / 回望
- 知识：巽位 / 群峰
- 成长：震位 / 登峰碑
- 个人：坤位 / 行者档案

卦位是信息架构的视觉索引，不承担服务端权限判断。权限、会话、奖励、掌握度和完成状态仍由服务端契约决定。

## 5. 视觉系统

### 5.1 Design Tokens

基础 Token 统一放在客户端设计系统中，业务页面不得散落硬编码颜色、圆角和动画时长。

| Token | 值 | 用途 |
| --- | --- | --- |
| `paper-0` | `#F4F0E6` | 主内容底色 |
| `paper-1` | `#E8E0D1` | 纸面层次 |
| `ink-950` | `#121A1D` | 深墨背景、强对比文本 |
| `ink-800` | `#233239` | 墨蓝内容层 |
| `rock-500` | `#69716E` | 辅助文字、岩灰线条 |
| `amber-500` | `#C79A4A` | 进度、焦点、完成状态 |
| `cinnabar-500` | `#A9473B` | 警示、重要印记，严格限量 |
| `mist-100` | `rgba(244,240,230,.68)` | 云雾透光层 |
| `line-ink` | `rgba(18,26,29,.18)` | 墨线、分隔线 |

圆角保持 4px 至 8px，卡片只用于重复条目、弹窗和真正需要框定的工具；页面大区使用整屏场景、纸面长卷和无边界布局。

### 5.2 字体与排版

- 正文优先使用系统中文无衬线字体栈，确保跨平台清晰度。
- 章节标题可以使用一款具有东方气质的显示字体，但只用于短标题和章节印记。
- 标题、正文、辅助文字、数据标签采用稳定的 4 级层级，不依赖超大字制造壮观感。
- 不使用负字距，不用视口宽度直接缩放字号；通过容器约束与断行保证移动端可读。

### 5.3 材质与图形

- 宣纸纤维只作为低透明度底纹，避免噪声影响文字。
- 湿墨晕染用于进入、完成和转场，干笔边缘用于分区和焦点。
- 细金线、卦爻线、星轨线作为状态图形，不做满屏装饰。
- 太极用于平衡、能量和进度；八卦用于方向、章节和知识维度。
- 云雾是空间层，不能覆盖题目、正文和主要按钮。

## 6. 云海与动态系统

### 6.1 四层云雾

1. **远景云海：** 低对比、慢速度，负责山体纵深。
2. **中景山谷雾：** 随滚动产生轻微视差，连接页面章节。
3. **近景湿墨雾：** 用于页面进入、完成反馈和短转场。
4. **山顶云障：** 与真实阶段进度绑定，逐步揭开远方峰顶。

云雾不做随机粒子，不遮挡功能内容，不用高耗能实时模拟。优先使用 CSS transform、opacity、mask 与少量预处理图层，资源按需加载。

### 6.2 动效节奏

| 场景 | 时长 | 动作 |
| --- | --- | --- |
| 页面进入 | 420-680ms | 云层退开、章节标题显现、方位点亮 |
| 导航展开 | 280-420ms | 太极旋转、八方展开、卦爻依次亮起 |
| 完成反馈 | 360-520ms | 墨滴扩散、金线沿山路上行、状态落定 |
| 页面转场 | 520-760ms | 云带横移或长卷折叠，保留可跳过入口 |
| 数据进入 | 240-420ms | 数值和轨迹从下方进入，不跳动布局 |

动画时长是表现层 Token，不能阻塞操作。`prefers-reduced-motion: reduce` 下暂停视差、旋转和持续运动，只保留必要的透明度与状态切换。

### 6.3 登顶状态

阶段完成页不使用普通成功弹窗，而是进入短暂的破晓全景：

1. 云海下沉，山顶露出。
2. 已完成路线以细金线连接。
3. 太极平衡稳定，成就印记落在登峰碑上。
4. 显示可访问的总结内容与下一步按钮。
5. 用户可以选择“回望来路”或“进入下一阶段”。

动画失败、资源加载失败或用户跳过都不能影响业务结果和后续导航。

## 7. 数据与状态边界

- 演示数据集中在客户端 adapter，显式标记 `demo`，不散落在组件文案中。
- UI 可以表达“请求中”“待审核”“需要复核”“暂无数据”等状态，但不能把客户端动画完成当作服务端结算完成。
- 服务端返回的掌握度、奖励、等级、任务完成和审核状态是唯一业务来源。
- AI 助手只调用服务端 AI Gateway；客户端不保存 Provider 密钥，不直接访问模型供应商。
- 加载、错误、权限与审核页复用同一个世界状态容器，保留请求 ID、可重试动作和安全说明。

## 8. 可访问性、性能与响应式验收

### 8.1 可访问性

- 键盘可访问导航、弹窗、菜单、表单和主要行动。
- 焦点环使用高对比墨金线，不依赖颜色单独传达状态。
- 题目、答案、数据和状态使用语义 HTML 与可读标签。
- 触摸区域不小于 44px，动态内容不会把焦点移到不可见区域。

### 8.2 性能

- 大图使用稳定资产 ID 对应的可替换资源路径，首屏只加载当前章节需要的图层。
- 云雾层优先合成属性，避免滚动时触发布局重排。
- 图片懒加载，加载失败提供纸面/墨线降级。
- 移动端减少图层数量和持续动画，避免影响学习任务输入。

### 8.3 验收清单

- 桌面端至少检查 1440px、1280px、1024px。
- 移动端至少检查 390px、375px，并验证横向滚动宽度等于视口宽度。
- 检查无文字遮挡、按钮溢出、卡片嵌套过深和异常跳动。
- 检查控制台错误、失败请求、图片 404、键盘焦点和移动端触摸路径。
- 检查减少动态效果、网络失败、空数据、待审核和无权限状态。
- 关键页面输出桌面与移动端截图，记录视口、资源版本和验证时间。

## 9. 第一阶段实现边界

第一阶段交付：

- `apps/user_client` 可运行的 Web 应用壳层。
- 全局 Token、App Shell、八方导航、太极状态轴和云海转场。
- 首页世界入口与演示态登山路径。
- 登录/欢迎、目标、计划、学习、复习、知识、AI 助手、成长、地图、个人中心页面的统一结构。
- 统一加载、错误、空数据、审核和权限状态。
- 真实资源 ID 接入与素材失败降级。
- 桌面/移动响应式适配、键盘焦点和减少动效支持。
- 页面截图与浏览器验证记录。

第一阶段不包含：

- 自行发明真实用户数据、真实机构、真实学习结果或支付结果。
- 客户端自行结算掌握度、经验、能量、奖励或等级。
- 重新生成一批未审阅的素材替代已有资源。
- 把完整 3D 引擎、音频系统或服务端业务模块塞进 UI 基座。

## 10. 完成定义

只有在以下证据齐全后，才能称为本轮 UI 改造完成：

1. 页面路由和组件均运行在统一 App Shell 内。
2. 视觉 Token、导航、云雾动效和状态反馈被多个页面复用。
3. 核心学习功能区域在动效开启与关闭时都可完成操作。
4. 桌面与移动端通过浏览器检查，无横向溢出、关键遮挡、控制台错误和资源加载失败。
5. 键盘、触摸、减少动效、加载失败、空数据、权限和审核状态有可验证行为。
6. 真实资源按稳定 `asset_id` 引用，演示数据有明确边界。
7. 设计前后页面清单、视觉规范、动效规范和关键截图可交付。
