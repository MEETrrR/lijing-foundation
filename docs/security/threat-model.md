# Threat Model

## Scope and assumptions

This model covers the public user clients, admin Web client, `/api/v1` API, modular domain services, workers, PostgreSQL, Redis, message bus, private object storage/CDN, AI Gateway, provider adapters, logs, and evidence exports.

The client is compromised by default: a user can modify binaries, requests, clocks, local storage, headers, prompts, uploads, and retry behavior. Provider credentials, database credentials, signing keys, and production secrets are server-side only. A successful control must therefore be enforced at the server boundary and remain safe under duplicate, reordered, delayed, or malicious input.

## Risk register

| Threat | Assets and abuse path | Preventive controls | Detection | Response and recovery |
|---|---|---|---|---|
| Token abuse and AI cost drain | A bot creates accounts or replays AI requests across accounts, devices, or IPs to consume provider budget. | AI Gateway is the only provider path; enforce identity/risk checks, new-account 24-hour quota of 5/day, normal quota of 20/day, burst limit of 3/10 minutes per account/device/IP, per-user concurrency 1, token and image caps, idempotency, global budget, and feature kill switches. | Alert on cost/request slope, denial-rate changes, account-device-IP clusters, duplicate fingerprints, concurrency saturation, and quota exhaustion. | Freeze the affected feature or risk cohort, switch to a low-cost/template/async fallback, preserve the usage ledger, revoke suspicious sessions, block abusive keys/IPs, and reconcile provider and internal cost records before restoring. |
| Prompt injection and tool overreach | User prompts, uploaded files, or retrieved content instruct the model to reveal data, change policy, call tools, or ignore system rules. | Separate system instructions, user input, retrieval, and tool arguments; allowlist tools and arguments; no model database access; source allowlists; output schema and sensitive-content checks; treat retrieved/uploaded text as data, not authority. | Log prompt/policy versions, tool decision codes, blocked patterns, output validator failures, and regression-case results without storing complete conversation bodies. | Deny the tool action, return a safe response, quarantine the source or prompt template, disable the affected tool/feature, add a minimized regression case, roll back the prompt/model route, and review impacted outputs. |
| Account takeover and OTP abuse | Attackers enumerate accounts, brute-force OTPs, steal refresh credentials, or abuse password reset and session refresh. | Short-lived OTPs and tokens, attempt limits, account/device/IP throttles, generic account responses, refresh-token rotation and revocation, secure Cookie or OS secure storage, MFA for admins/high-risk actions, and risk-based re-verification. | Monitor OTP failure/velocity, reset spikes, impossible travel/device changes, refresh-token reuse, session fan-out, and admin MFA failures. | Revoke the account's sessions and refresh chain, require re-verification, rate-limit or challenge the source, notify the user through a trusted channel, preserve auth audit records, rotate affected secrets, and investigate privilege changes. |
| Reward replay and settlement forgery | A client changes timestamps or submits `correct`, `mastery`, `reward`, `energy`, or completion values, or replays a successful action to duplicate settlement. | Server-authoritative state machines and ledgers, server time, immutable attempt facts, idempotency keys, event de-duplication, bounded transition rules, and API schemas that accept intent rather than final results. | Alert on duplicate keys with payload changes, settlement fan-out, impossible completion times, repeated answer fingerprints, negative or excessive balance deltas, and event consumer lag/replay errors. | Stop affected settlement, quarantine the actor or cohort, retain raw audit/event evidence, rebuild projections from facts, issue compensating ledger entries rather than editing history, and only unfreeze after replay and balance checks pass. |
| Malicious uploads, SSRF, or file bombs | An uploaded image/document or URL exploits parsers, reaches internal services, consumes worker resources, or serves active content. | Private quarantine storage, size/pixel/page limits, extension plus magic-byte MIME checks, virus/script/archive scanning, EXIF removal, URL scheme/host allowlists, no arbitrary server fetch, isolated OCR/parser workers, timeouts, and egress restrictions. | Detect scan failures, decompression ratios, parser timeouts, blocked schemes/hosts, unexpected egress, worker memory/CPU spikes, and repeated malicious signatures. | Keep the object quarantined, deny processing and public access, block the source, capture hashes and scan evidence, rotate temporary access, patch or disable the parser, purge derived artifacts, and reprocess only after a clean scan. |
| UGC or AI-content poisoning | Incorrect, copyrighted, unsafe, or adversarial content enters a public question, explanation, retrieval index, or Boss flow and spreads. | Draft/review/publish states, source and copyright fields, content/version IDs, answer verification, knowledge-point matching, human sampling, provenance in retrieval, report/appeal/takedown/rollback, and no direct AI-to-public publication. | Compare answer/error reports, duplicate and anomaly scores, source provenance gaps, report rate by version, retrieval-hit spikes, and moderation queue age. | Unpublish the exact version and downstream projections, preserve historical references, limit propagation, notify reviewers, correct with a new version, rebuild affected indexes, and publish a post-incident content-quality record. |
| PII leakage | Logs, AI context, exports, analytics, screenshots, or object URLs expose phone numbers, conversations, credentials, or private uploads. | Data classification, field-level access, minimization, encryption, private storage, short-lived signed URLs kept out of logs, redaction at ingestion, allowlisted AI context, export filtering, retention/deletion workflows, and access audits. | DLP scans for secret/phone/token patterns, unusual downloads, broad queries, log sink alerts, signed-URL leakage, and export anomalies. | Revoke URLs/tokens, stop the leaking path, preserve access logs, assess scope, notify the security/privacy owner, rotate affected credentials, purge derived copies within policy, and correct redaction tests before re-enable. |
| Supply-chain attack | A compromised dependency, package registry, build action, container, or generated asset introduces code or steals secrets. | Lockfile and approved registry, dependency review, vulnerability scanning, SBOM, signed/reproducible builds, minimal permissions, isolated CI, secret scanning, artifact provenance, and no install scripts from untrusted sources. | Monitor dependency advisories, checksum/signature drift, build provenance failures, unexpected network access, secret-scan findings, and anomalous artifact diffs. | Block release, identify affected versions and artifacts, revoke/rotate CI and runtime credentials, rebuild from a known-good dependency set, compare deployed hashes, and document impact before resuming. |
| DDoS and API abuse | Volumetric or application-layer traffic exhausts API, database, queue, worker, or AI resources; expensive endpoints amplify cost. | CDN/WAF, edge rate limits, body/time limits, route-specific quotas, authenticated expensive actions, cache/read shedding, bounded queues, circuit breakers, autoscaling with ceilings, and separate static delivery. | Track RPS, status codes, latency, queue depth, DB connections/locks, worker saturation, WAF events, and cost per request by route. | Apply edge blocks and route throttles, disable expensive features, serve read-only/degraded responses, protect login and settlement paths, scale within budget, preserve traffic samples, and lift limits gradually after the attack curve normalizes. |
| Admin misuse or internal privilege abuse | A privileged operator exports too much data, changes policy without review, deletes evidence, or misuses a kill switch. | MFA, scoped RBAC, just-in-time elevation, dual approval for high-risk changes, confirmation with impact preview, immutable audit trail, no ordinary-admin deletion, break-glass separation, and policy effective dates. | Alert on unusual scope/volume, after-hours actions, policy loosening, repeated failed MFA, audit gaps, bulk exports, and changes without a matching ticket/approval. | Suspend the account/session, revoke elevated access, activate break-glass incident control, freeze the affected change, restore the prior version, preserve audit evidence, review all impacted objects, and require security approval before access returns. |

## Trust boundaries

1. **Client to API:** every field is untrusted; authorization, quotas, validation, and settlement happen server-side.
2. **API to domain modules:** only application interfaces and versioned events cross module ownership; repositories do not cross boundaries.
3. **Domain to infrastructure adapters:** credentials and provider-specific details stay behind adapters and secret management.
4. **Worker to uploaded content:** quarantine and sandbox boundaries prevent parsers and OCR from reaching production facts or internal networks.
5. **AI Gateway to providers:** normalized requests, bounded context, provider timeout, retry, cost accounting, and output validation are mandatory.
6. **Operational users to admin API:** the admin UI is still a client; MFA, RBAC, approval, and auditing are enforced in the API.

## Security evidence

Every material decision should be reconstructable from `request_id`, actor/device risk summaries, policy/version IDs, event IDs, reason codes, and audit records. Evidence must be useful without retaining complete passwords, tokens, model keys, phone numbers, signed URLs, or conversation bodies in logs.

## Residual risk

This document defines engineering controls, not a certification or legal opinion. Abuse thresholds, retention periods, provider terms, Mainland China compliance obligations, and incident notification duties require review against the deployed product and current professional guidance before launch.
